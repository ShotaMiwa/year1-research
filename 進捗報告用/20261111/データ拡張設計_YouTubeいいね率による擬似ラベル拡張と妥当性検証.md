## 1. 背景とデータ拡張の目的

### 1.1 被験者アンケート（N=23）の制約と知見
- **対象データの実態**: ひろゆき氏の生配信アーカイブから抽出された **23セグメント（各34秒〜227秒、平均80.5秒）**。
- **セグメントの構造**: 視聴者からの質問・相談（スパチャ等）を読み上げ、回答して次の話題に移るまでの**「1問1答（Q&A）単位」**。
- **先行検証（11/11報告）で得られた重要知見**:
  1. 線形SVMは全12次元で過学習（Balanced Acc 65.1% → 52.4%）を起こし、少数特徴量制約が必須。
  2. ロジスティック回帰（L2）は全12次元で向上（54.4% → 61.5%）。
  3. 全モデル共通で **Question Ratio（疑問文比率）が最大の負の重み**、**Comment Semantic Variance（コメント意味分散）および Segment Length（動画尺）が最大の正の重み**として機能。

### 1.2 データ拡張の目的
- 被験者アンケート（$N=23$）の追加収集を行わずに、Web上の公開データを用いてサンプル規模を拡張（$N \sim 100$〜$300+$件）する。
- **基本戦略**:
  - ひろゆき公式切り抜き動画から**「いいね率（Like Rate）」**を取得して**擬似満足度ラベル**とする。
  - **切り抜き動画に対応する「元配信アーカイブの特定区間」を自動同定**し、その時間帯の**「生配信チャット（Live Chat）」**を抽出することで、アンケートと同一の12特徴量を完全に再現・生成する。
  - 外部データをいきなり学習に投入せず、**「3つの妥当性検証フィルター」**を通過したデータのみを拡張セットとして採用する。

## 2. データ収集仕様（ひろゆき切り抜き動画の選定基準）

アンケートデータの性質（ひろゆき配信・1問1答・30秒〜4分）を厳密に再現するため、以下の選定・足切り基準を設ける。

| 項目 | 選定基準・フィルタ条件 | 設定理由（統制の目的） |
| :--- | :--- | :--- |
| **対象チャンネル** | ひろゆき公認・大手切り抜きチャンネル（ひろゆきの部屋 等） | ひろゆき本人の発話・語彙・ファン層のベースラインを統一 |
| **動画の構成** | 単一の質問に答えている「1問1答形式」の動画 | アンケートの23セグメントの構造と1対1で対応させる |
| **動画の長さ（尺）** | **40秒 〜 4分以内（240秒以内）** | アンケートの実態（34s〜227s）と一致させ、Shortsや長編まとめ動画を排除 |
| **編集スタイル** | ジェットカット（無音間引き）が過剰でない動画 | 音声特徴量（発話速度 Speech Rate、無音率）の歪みを防止 |
| **再生回数の範囲** | **30,000回 〜 300,000回** | 再生不足によるいいね率の跳ね上がりや、極端なバズによるライト層ノイズを排除 |
| **公開からの経過時間** | 公開から **1ヶ月（30日）以上経過** | 熱狂的ファンのみが視聴する初期偏向を排し、エンゲージメント率を安定化 |

## 3. 元配信区間の特定と生チャット同期パイプライン（重要）

切り抜き動画の「動画コメント欄」ではなく、アンケート時と同様に**「生配信中のリアルタイムチャット」**を同期・抽出するため、以下の3段階照合パイプラインを実装する。

```text
┌────────────────────────────────────────────────────────────────────────┐
│  切り抜き動画（YouTube）                                                │
│  - いいね率（Like-to-View Ratio）を取得 ──► 擬似満足度ラベル             │
│  - 音声 / 自動字幕テキストを取得                                        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
       【元配信アーカイブの特定 & 時間区間アライメント】
       Step 1: 概要欄のメタデータ解析（元配信URL・タイムスタンプ取得）
       Step 2: 字幕テキストのローカルアライメント照合（秒単位の開始/終了特定）
       Step 3: 音声フィンガープリント照合（テキスト不一致時のフォールバック）
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  元配信アーカイブの該当区間 [Start_sec, End_sec]                       │
│  - 当該区間の音声波形（Speech Rate等 算出用）                           │
│  - 当該時間帯に投稿された「生配信チャット（Live Chat Replay）」         │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  アンケートと同一の全12特徴量を抽出・生成                               │
│  （Question Ratio, Comment Semantic Variance, Segment Length 等）       │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.1 元配信区間の特定手順

#### 手順1：概要欄メタデータ解析（高速・高精度）
- ひろゆき公認切り抜き動画は、概要欄に元動画のクレジット記載が義務付けられている。
- 正規表現により元配信動画IDとタイムスタンプを抽出：
  - URLパターン: `youtube.com/watch\?v=([a-zA-Z0-9_-]+)`
  - タイムスタンプパターン: `(?:t=|#t=)(\d+)s?` または `(\d{1,2}):(\d{2}):(\d{2})`
- 開始時刻 $T_{\text{start}}$ を特定し、切り抜き動画の長さ $L$ を加算して終了時刻 $T_{\text{end}} = T_{\text{start}} + L$ を確定。

#### 手順2：字幕テキストのローカルアライメント（フォールバック）
- 概要欄に正確な秒数記載がない場合、切り抜き動画の冒頭テキスト（最初の質問読み上げ部分）をキーとして、元配信全体の自動字幕テキストに対してファジーマッチング（Smith-Waterman法 / RapidFuzz）を実施。
- 最も類似スコアが高い区間の開始インデックス・終了インデックスから、秒単位の区間 $[T_{\text{start}}, T_{\text{end}}]$ を特定。

### 3.2 生チャット（Live Chat Replay）の取得
- 特定した元配信IDに対し、`chat-downloader` または YouTube Data API を用いて生配信チャットログ全件（タイムスタンプ付き）を取得。
- $[T_{\text{start}}, T_{\text{end}}]$ に投稿されたコメントのみをスライス抽出。
- 既存の特徴量抽出器に渡し、`comment_rate`, `comment_semantic_variance`, `grass_ratio`, `sentiment_polarity` などのコメント系特徴量を完全再現する。

## 4. 妥当性検証プロトコル（3つの整合基準）

取得した追加データセットについて、学習データへ合流させる前に以下の3つの基準で妥当性を検定する。

```text
┌──────────────────────────────────────────────────────────────────────┐
│  追加データ（N件）：12特徴量 ＋ Like Rate                            │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │
                                   ▼
          【妥当性検証フィルター（3つの整合基準）】
          1. 特徴量変化の向きの一致検定（Mann-Whitney U検定）
          2. アンケート学習モデルによるゼロショット予測（順位相関 / 判別能）
          3. 特徴量空間の分布乖離度チェック（PCA / OOD検定）
                                   │
                                   ├─ [合格] ──► 本番のデータ拡張セットへ合流
                                   │
                                   └─ [不整合] ► 「主観評価と公開行動の乖離」
                                                 として学術的考察に昇華
```

### 基準1: 主要特徴量の変化の向き（Directionality）の一致
- Like Rate の上位群（High）と下位群（Low）の間で、アンケートで支配的だった特徴量が同じ方向に有意差を示すか検証。
  - **Question Ratio**: High群で有意に低いこと（トーク停滞の抑制）
  - **Comment Semantic Variance**: High群で有意に高いこと（コメント語彙の豊かさ）
  - **Segment Length**: High群で有意に長いこと（十分な文脈展開）

### 基準2: アンケート学習モデルによるゼロショット評価
- アンケートデータ（$N=23$）で学習したモデル（線形SVM / ロジスティック回帰）で追加データを推論。
- 予測確率 $\hat{P}(\text{High})$ と実際の Like Rate との**スピアマン順位相関 $\rho > 0$（有意水準 $p < 0.05$）**を確認。

### 基準3: 特徴量空間のドメイン乖離度（OODチェック）
- アンケートセグメントの12次元特徴量分布に対し、追加データの主成分得点（PCA）が外れ値領域に飛んでいないか（Mahalanobis距離等で判定）を確認。

## 5. データ拡張後の学習・評価実験計画

妥当性検証をクリアしたデータを用い、以下の3手法で汎化性能を検証する。

1. **合併学習（Merged Training）**:
   - アンケート（$N=23$）＋ 追加データ（$N=100\sim 200$）を直接結合し、全12次元ロジスティック回帰・線形SVMの汎化精度（アンケートテスト集合に対する評価）を測定。
2. **重み付き合併学習（Sample Weighted）**:
   - アンケートの真のラベルを $w=1.0$、追加データの擬似ラベルを $w=0.5$ として損失関数を最適化。
3. **事前学習・ファインチューニング**:
   - 追加データ（Like Rate）で多次元重みを事前学習し、アンケートデータで最終層を微調整。
